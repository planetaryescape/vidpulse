# Chrome Storage Caching

Project uses Chrome storage APIs with sophisticated cache invalidation, version-based preferences tracking, and security separation between local/sync storage.

## Cache Entry Structure

Cache entries include analysis AND original video content for chat feature:

```typescript
// From storage.ts setCache()
const entry: CacheEntry = {
  videoId,
  analysis,
  videoContent,  // Raw video content for chat context
  timestamp: Date.now(),
  preferencesVersion: settings.preferencesVersion,
};
await chrome.storage.local.set({ [key]: entry });
```

Key pattern: Store video content alongside analysis so chat can reference original material without re-reading video.

## Preference Version Invalidation

Cache invalidates when preferences change (not just time):

```typescript
// From storage.ts getCached()
if (entry.preferencesVersion !== settings.preferencesVersion) {
  await chrome.storage.local.remove(key);
  return null;
}
```

Version bumps on:
- `aboutMe` changes
- Any model configuration changes
- Memory additions (learned preferences)

```typescript
// From storage.ts saveSettings()
function preferencesChanged(current: Settings, updates: Partial<Settings>): boolean {
  if ("aboutMe" in updates && updates.aboutMe !== current.aboutMe) {
    return true;
  }
  if ("models" in updates && updates.models) {
    for (const key of Object.keys(newModels) as (keyof ModelConfig)[]) {
      if (newModels[key] !== currentModels[key]) {
        return true;
      }
    }
  }
  return false;
}

// Auto-increment version
let newVersion = current.preferencesVersion;
if (!options?.skipVersionIncrement && preferencesChanged(current, settings)) {
  newVersion = (current.preferencesVersion || 1) + 1;
}
```

Skip increment when called from auto-regeneration (already incremented by `addMemory`):

```typescript
// From service-worker.ts REGENERATE_ABOUT_ME handler
await saveSettings(
  { aboutMe, aboutMeAutoGenerated: true },
  { skipVersionIncrement: true },  // Already bumped by addMemory
);
```

## Storage Separation (Security)

**API keys → chrome.storage.local (NOT synced):**

```typescript
// From storage.ts getApiKeys()
async function getApiKeys(): Promise<ApiKeys> {
  const result = await chrome.storage.local.get(API_KEYS_KEY);
  return (result[API_KEYS_KEY] as ApiKeys | undefined) || { apiKey: "" };
}
```

**Settings → chrome.storage.sync (synced across devices):**

```typescript
// From storage.ts saveSettings()
const { apiKey: _apiKey, braveApiKey: _braveApiKey, ...syncableUpdates } = settings;
const syncData = { ...current, ...syncableUpdates, preferencesVersion: newVersion };
delete (syncData as Record<string, unknown>).apiKey;
delete (syncData as Record<string, unknown>).braveApiKey;

await Promise.all([
  chrome.storage.sync.set({ settings: syncData }),
  Object.keys(apiKeyUpdates).length > 0 ? saveApiKeys(apiKeyUpdates) : Promise.resolve(),
]);
```

Pattern: Strip API keys before sync storage. Parallel saves to both storage areas.

## In-Memory Settings Cache

Settings cached to avoid repeated storage reads:

```typescript
// From storage.ts
let settingsCache: Settings | null = null;

export async function getSettings(): Promise<Settings> {
  if (settingsCache) return settingsCache;

  const [syncResult, apiKeys] = await Promise.all([
    chrome.storage.sync.get("settings"),
    getApiKeys(),
  ]);
  const syncSettings = (syncResult.settings || {}) as Partial<Settings>;
  settingsCache = {
    ...DEFAULT_SETTINGS,
    ...syncSettings,
    apiKey: apiKeys.apiKey || "",
    braveApiKey: apiKeys.braveApiKey,
  };
  return settingsCache;
}

export async function saveSettings(settings: Partial<Settings>, options?: { skipVersionIncrement?: boolean }): Promise<void> {
  // Invalidate cache BEFORE saving
  settingsCache = null;

  const current = await getSettings();
  // ... save logic ...

  // Invalidate cache AFTER saving to ensure fresh data on next read
  settingsCache = null;
}
```

**Critical pattern:** Invalidate cache before AND after save. Before ensures fresh read during save. After ensures next read gets fresh data.

## Time-Based Expiry

Configurable cache expiry in days:

```typescript
// From storage.ts getCached()
const expiryMs = settings.cacheExpiry * 24 * 60 * 60 * 1000;
if (Date.now() - entry.timestamp > expiryMs) {
  await chrome.storage.local.remove(key);
  return null;
}
```

Default: 365 days (1 year). User-configurable in settings.

## Automatic Cleanup

Runs on startup to remove stale cache:

```typescript
// From storage.ts cleanupCache()
export async function cleanupCache(): Promise<void> {
  const settings = await getSettings();
  const expiryMs = settings.cacheExpiry * 24 * 60 * 60 * 1000;
  const all = await chrome.storage.local.get(null);

  const keysToRemove: string[] = [];
  for (const [key, value] of Object.entries(all)) {
    if (key.startsWith(CACHE_PREFIX)) {
      const entry = value as CacheEntry;
      // Remove if expired OR preferences version mismatch
      if (
        Date.now() - entry.timestamp > expiryMs ||
        entry.preferencesVersion !== settings.preferencesVersion
      ) {
        keysToRemove.push(key);
      }
    }
  }

  if (keysToRemove.length > 0) {
    await chrome.storage.local.remove(keysToRemove);
  }
}

// From service-worker.ts
chrome.runtime.onStartup.addListener(() => {
  cleanupCache();
});
```

Cleanup checks BOTH time expiry and version mismatch.

## Model ID Migration Pattern

One-time migrations for incorrect/deprecated model IDs:

```typescript
// From storage.ts
const MODEL_ID_FIXES: Record<string, string> = {
  // Missing prefix
  "gemini-3-flash-preview": "google/gemini-3-flash-preview",
  // Wrong model IDs (OpenRouter uses different names)
  "google/gemini-2.0-flash": "google/gemini-2.0-flash-001",
};

function fixModelId(modelId: string): string {
  if (MODEL_ID_FIXES[modelId]) {
    return MODEL_ID_FIXES[modelId];
  }
  // If model doesn't have a provider prefix, add google/
  if (!modelId.includes("/")) {
    return `google/${modelId}`;
  }
  return modelId;
}

export async function migrateModelIds(): Promise<void> {
  const syncResult = await chrome.storage.sync.get("settings");
  const syncSettings = (syncResult.settings || {}) as Partial<Settings>;

  if (!syncSettings.models) return;

  const models = syncSettings.models;
  let needsMigration = false;

  for (const key of Object.keys(models) as (keyof ModelConfig)[]) {
    const modelId = models[key];
    if (modelId && modelNeedsMigration(modelId)) {
      needsMigration = true;
      break;
    }
  }

  if (needsMigration) {
    const fixedModels: ModelConfig = {
      videoReading: fixModelId(models.videoReading || DEFAULT_MODELS.videoReading) as VideoModel,
      // ... fix all models ...
    };

    await chrome.storage.sync.set({
      settings: { ...syncSettings, models: fixedModels },
    });
  }
}

// From service-worker.ts - run on startup
migrateModelIds().catch(() => {});
```

Pattern: Check for migration needed, apply fixes, save once. Runs silently on startup.

## Session Storage (Short-lived)

Uses `chrome.storage.session` for temporary data cleared on browser close:

```typescript
// From storage.ts
const SESSION_INACTIVITY_TIMEOUT = 30 * 60 * 1000; // 30 minutes

export async function getSession(): Promise<SessionData | null> {
  const result = await chrome.storage.session.get(SESSION_KEY);
  const session = result[SESSION_KEY] as SessionData | undefined;

  if (!session) return null;

  // Check for inactivity timeout
  if (Date.now() - session.lastActivity > SESSION_INACTIVITY_TIMEOUT) {
    await chrome.storage.session.remove(SESSION_KEY);
    return null;
  }

  return session;
}
```

Pattern: Automatically expire session data after 30min inactivity.

## Avoid

- DON'T sync API keys (security risk)
- DON'T forget to invalidate settings cache before AND after save
- DON'T skip version increment when preferences change (breaks cache invalidation)
- DON'T forget `skipVersionIncrement: true` when auto-regenerating (already bumped)
- DON'T store video content in analysis object itself (separate `videoContent` param)
